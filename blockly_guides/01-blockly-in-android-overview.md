# מדריך 01: סקירת ארכיטקטורה — Blockly Android המודרנית

## 💡 למה תוכננה ארכיטקטורה חדשה?

בעבר, שילוב של Blockly ב-Android נעשה באחת משתי דרכים בעייתיות:
1. **WebView מלא עם קוד JavaScript של Blockly Web**: צריכת זיכרון אדירה (מעל 100MB RAM), איטיות במגע, בעיות סנכרון וגשר אסינכרוני מסורבל (`evaluateJavascript`).
2. **הספרייה הישנה של גוגל מ-2015**: ננטשה לפני כעשור, מסתמכת על מחלקות שהוצאו משימוש (Deprecated), בעלת מערכת קבצים מורכבת שמצריכה שכפולי קבצים ועשרות תלויות.

**Blockly Android החדשה נבנתה כספריית Pure Native מודרנית ונקייה.**

## 🔑 יתרונות המבנה החדש

### 1. ביצועים קיצוניים (Ultra-Fast Performance)
* ציור ישיר באמצעות `android.graphics.Canvas` ו-`Path`.
* שימוש ב-Double Buffering טבעי של מערכת ה-UI של Android.
* צריכת זיכרון של פחות מ-5MB RAM בלבד.

### 2. צימוד מינימלי (Zero External Dependencies)
* דורש רק תלויות סטנדרטיות של `androidx.appcompat` ו-`material`.
* עיבוד JSON ישיר מובנה (`org.json`).
* ללא צורך במנועי Rhino, V8, WebView או רכיבי NDK.

### 3. תאימות מודרנית מלאה
* תומך ב-**Java 17 / Java 21**.
* תומך בגרסאות ה-SDK המודרניות: **compileSdk 34+**, **minSdk 21+**.
* 0 שגיאות Deprecation ו-0 אזהרות קומפילציה.
